# 实验室服务器与资源使用规则

## 项目目标

Aurora 做的是工业时序数据的异常检测。当前阶段目标是复现 baseline 并完成 seed 消融，
不是提出新模型。理解这一点之前不要改代码。

## 数据位置

| 内容       | 路径                   | 权限       | 说明                         |
| ---------- | ---------------------- | ---------- | ---------------------------- |
| 训练数据   | `/data/aurora/v3`      | 只读       | 已冻结的正式快照             |
| 中间缓存   | `/data/aurora/cache/`  | 本人可清理 | 复现前必须确认此目录为空     |
| 实验输出   | `/scratch/aurora/<名字>` | 读写     | 每人一个目录，两周内自清理   |

## 服务器与排队规则

- 服务器为实验室内网机器，地址与账号只在本机记录，不写进仓库、不贴进群聊。
- 单次作业最长 8 小时，超过需重新申请；夜间 23:00–07:00 优先留给长任务。
- 同一时间每人最多占用一张卡，用完立即释放。

## 资源申请流程

1. 在组内值班表登记：实验名、预计卡时、是否需要 `/scratch` 配额。
2. 值班同学确认排期后发放临时账号。
3. 把实验名与占用时段回报到交接记录里，避免和别人的实验撞车。

## 资源释放流程

1. 训练结束先停止进程，确认卡已空出。
2. 清理 `/scratch/aurora/<名字>` 下不再需要的中间文件，只保留指标和配置。
3. 退出临时账号，在值班表上把条目改成「已释放」。

## 禁止事项

- 禁止直接在服务器上改配置后跑实验：所有配置改动必须落到一份新的配置文件里。
- 禁止把 `/data/aurora/v3` 当作可写目录，也禁止删除历史实验记录。
- 禁止把服务器地址、账号、任何凭据写进代码、笔记或聊天记录；
  LabRelay 导入时会命中凭据检测并把整份资料标为受限，见 `notes/credential_scan_demo.md`。
- 禁止自动执行任何运维动作，交接系统只给建议，不代跑命令。
